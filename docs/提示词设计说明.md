# 提示词设计说明 — 医学教材知识图谱

> 配套 [医学教材知识图谱构建.html](医学教材知识图谱构建.html) 的工程落地版本。
> 系统已 seed 一条示范模板 **"医学教材章节图谱（基础护理学示范）"**，admin 登录后在 [/templates](http://localhost:3000/templates) 即可查看、编辑、调用。

---

## 一、模板调用链路

```
admin 在 /templates 维护提示词
        │
        ▼
expert 在 /graphs/:id "AI 生成图谱" 弹窗里
  - 选模板
  - 填变量（教材 / 章 / 节 / 原文 / 是否抽能力点 ...）
        │
        ▼
POST /api/ai/generate { template_id, variables, graph_id }
        │
        ▼
后端 ai.orchestrator
  - Handlebars 渲染 user_prompt_template + 变量
  - 调 LLM（base_url/api_key/model 取自 SystemSettings 的 DB 覆盖层，不是 .env）
  - Zod 校验 LLM 输出（必须是 { graph_name, nodes[], relations[] }）
  - 节点/关系全部以 status="candidate" 落库 Neo4j
        │
        ▼
expert 在画布右侧 ReviewPanel 审核 → approve / reject
```

**关键：模板里写的是给 LLM 的指令；LLM 必须按 JSON Schema 直出节点和关系。系统不再做"二次抽取"，所以提示词的精度就是结果的精度。**

---

## 二、目前 seed 的两个模板

### 1. `医学教材章节图谱（基础护理学示范）`

**适用场景**：从一节教材正文（500–2000 字）里抽出完整图谱片段。

**变量**：
| key | 类型 | 必填 | 说明 |
|---|---|---|---|
| `textbook` | text | ✓ | 教材名，默认"基础护理学" |
| `edition` | text | | 版本，默认"第7版" |
| `chapter` | text | ✓ | 章名，例 "静脉输液与输血" |
| `section` | text | ✓ | 节名，例 "静脉输液" |
| `page_no` | number | | 起始页码 |
| `source_text` | textarea | ✓ | 教材原文，建议 500–2000 字 |
| `extract_competency` | boolean | | 是否抽取能力点，默认 true |

**system_prompt 关键约束**：

- 9 类节点（textbook/chapter/section/knowledge_point/term/operation_step/competency/image/table）
- 9 类关系（CONTAINS/BELONGS_TO/PREREQUISITE_OF/EASILY_CONFUSED_WITH/RELATED_TO/ILLUSTRATED_BY/DESCRIBED_IN/STANDARD_TERM_OF/SYNONYM_OF/SUPPORTS_COMPETENCY）
- 12 类 knowledge_type 枚举（与 [shared/src/enums.ts](shared/src/enums.ts) 一致）
- 切片硬规则：一个 knowledge_point 只解决一个教学问题；操作类按"准备/核对/穿刺/调速/观察/记录/异常处理"切；术语必须给标准词 + 别名；confidence 分档；status 全部 candidate
- node_id 用短下划线英文，关系 source_id/target_id 必须命中已输出的 node_id

**user_prompt_template** 用 Handlebars `{{var}}` + `{{#if var}}...{{/if}}` 控制能力点抽取开关。

### 2. `医学术语标准化（同义词扩展）`

**适用场景**：给一个术语原文（教材正式说法 / 临床表达 / 学生口语都行），输出标准术语 + 0–4 个同义词节点。用于丰富已有图谱的 term 层。

## 三、LLM 必须输出的 JSON Schema

根对象（[shared/src/schemas/ai.ts:24](shared/src/schemas/ai.ts#L24)）：

```jsonc
{
  "graph_name": "基础护理学 - 静脉输液与输血 - 静脉输液",
  "nodes": [
    /* Node 数组 */
  ],
  "relations": [
    /* Relation 数组 */
  ],
}
```

### Node（discriminated union by `node_type`）

公共字段（[shared/src/schemas/node.ts:16](shared/src/schemas/node.ts#L16)）：

```jsonc
{
  "node_id": "kp_iv_extravasation", // 必填，关系会引用它
  "node_type": "knowledge_point", // 必填，决定后面的字段
  "name": "输液外渗的识别与处理", // 必填
  "status": "candidate", // AI 输出固定 candidate
  "confidence": 0.85, // 0–1
  "source": "ai_generated",
  "description": "...", // 可选
  "tags": ["静脉输液", "异常处理"],
}
```

按 `node_type` 加字段：

- `knowledge_point`：`knowledge_type`（必填，12 类枚举）+ `textbook` / `chapter` / `section` / `page_no` / `difficulty` / `importance`
- `term`：`standard_term`（必填）+ `aliases[]` + `english` + `category`
- `operation_step`：`step_order`（必填，整数）+ `phase`（必填，如 "准备" / "穿刺" / "观察"）
- `competency`：`competency_level`（"核心能力" / "基础能力" / "支持能力"）+ `domain`
- `image`：`url`（先留空）+ `caption`
- `table`：`columns[]` + `summary`
- `textbook`：`edition` / `publisher` / `publish_year`
- `chapter`：`chapter_no` / `page_range`
- `section`：`section_no`

### Relation

```jsonc
{
  "source_id": "kp_iv_extravasation", // 必须命中 nodes[] 里的 node_id
  "target_id": "comp_abnormal_recognition",
  "relation_type": "SUPPORTS_COMPETENCY", // 15 类枚举之一
  "status": "candidate",
  "confidence": 0.85,
}
```

15 种 relation_type：[shared/src/enums.ts:43](shared/src/enums.ts#L43)。

## 四、HTML 文档想要的能力 vs 系统现状

把 HTML 里 ChatGPT 提到的 10 个核心环节 / 9 个壁垒，对照当前系统能力：

| HTML 提到的能力                          | 当前系统支持度                                      | 差距 / 落地方式                                                                                                      |
| ---------------------------------------- | --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **教材结构（textbook→chapter→section）** | ✅ 节点类型 + BELONGS_TO 关系全有                   | 直接用                                                                                                               |
| **知识点切分（按教学语义）**             | ✅ knowledge_point + 12 类 knowledge_type           | 提示词里写硬规则就能落                                                                                               |
| **术语标准化（标准词 + 别名）**          | ✅ term 节点 + STANDARD_TERM_OF / SYNONYM_OF        | 直接用                                                                                                               |
| **操作步骤（按 phase 切）**              | ✅ operation_step + step_order + phase              | 直接用                                                                                                               |
| **能力点（异常识别 / 操作规范 …）**      | ✅ competency + SUPPORTS_COMPETENCY                 | 直接用                                                                                                               |
| **图片处理**                             | ⚠️ image 节点存在但只有 url + caption               | HTML 想要的 oss_key / visual_summary / bbox / related_text_block_ids 目前塞 description 或 tags；MVP 后期再扩 schema |
| **表格处理**                             | ⚠️ table 节点有 columns + summary                   | HTML 想要的 html / markdown / row 级知识点关联待扩                                                                   |
| **page_no / bbox 证据定位**              | ⚠️ knowledge_point 有 page_no，但没 bbox / block_id | 当前精度到"页"，做不到"段落 bbox 高亮"。MVP 阶段够，要做"点击答案高亮原文"才需要补                                   |
| **题库关联（question→knowledge_point）** | ✅ question 节点 + TESTED_BY                        | 题库本身入库需要单独流程，但 schema 已就位                                                                           |
| **病例关联（case→knowledge_point）**     | ✅ case 节点 + APPLIED_IN                           | 同上                                                                                                                 |
| **易混淆 / 前置知识**                    | ✅ EASILY_CONFUSED_WITH / PREREQUISITE_OF           | 直接用                                                                                                               |
| **图文一体化检索 / embedding**           | ❌ 当前只是图谱，没有向量化 / 检索 / RAG 回答       | 这是图谱**之后**的事；图谱负责结构化知识，RAG / Agent 调用是下一期                                                   |
| **证据引用（页码 + 段落 + 图）**         | ⚠️ page_no 有，段落级 chunk_id 没有                 | 同 bbox                                                                                                              |
| **评测集 / 回归测试**                    | ❌ 系统层面没有                                     | 需要单独的评测模块                                                                                                   |
| **自动学习路径 / 学情分析**              | ❌ 没有                                             | 需要学生 / 答题数据，超出图谱范围                                                                                    |

**结论**：HTML 文档要的能力，系统**结构层 90% 已具备**（节点类型 + 关系类型完整），缺的是：

1. image / table 节点的精细字段（oss_key / bbox / 行级标注）→ 临时塞 description；要做"点击高亮"再扩 schema
2. embedding / RAG / Agent 调用层 → 图谱之外的另一个项目，本期不做
3. 评测集 → 等图谱有数据后再上

## 五、修改 / 新建提示词的步骤

1. admin 登录 → 顶部菜单 **提示词模板**
2. 点 **新建模板** 或编辑现有的"医学教材章节图谱（基础护理学示范）"
3. 三段必填：
   - **变量定义** — key 用英文下划线，type 选 textarea / text / select / number / boolean
   - **System Prompt** — 写 LLM 的"角色 + 硬规则 + 输出格式"。**不要**塞用户输入。
   - **User Prompt Template** — 用 `{{key}}` 引用变量，可用 `{{#if key}}...{{/if}}` 条件块。**用户输入只能从这里进**。
4. **Output Schema**（可选）— 写 JSON Schema 卡格式，会作为 zod 校验前的提醒。**不会**变成 OpenAI 的 `response_format`，那个由后端控制。
5. 保存 → 立刻可用。

## 六、调用前你必须先做的事

1. **配 LLM Key**：admin → **系统设置** → 填 base_url / model / API Key → 保存。**不需要重启后端**，下一次 AI 调用就生效。
2. **建一个空图谱**：[/graphs](http://localhost:3000/graphs) 新建。
3. **AI 生成图谱**：进图谱 → 右上角 "AI 生成图谱" → 选模板 → 填教材原文 → 提交 → 等结果 → 在右侧 ReviewPanel 一条条审核。

## 七、给"静脉输液"章节的实操建议

- 第一次跑：只贴**一节**（不要一次贴一章）。500–2000 字最稳。
- 选 GPT-4o / Claude Sonnet 4.5 级别就够了，章节加工任务不需要 Opus。
- 跑出来的 candidate 一定**人工审一遍再 approve**：尤其检查
  - knowledge_type 分类是否合理
  - operation_step 的 step_order 是否连续
  - term 的 aliases 有没有遗漏学生口语（"针眼鼓包" / "局部肿胀" 这类）
  - EASILY_CONFUSED_WITH 关系是否真的易混（输液外渗 vs 静脉炎是真混；输液外渗 vs 输液速度调节就不是）
- 全章节都跑完后，回头看 graph_name 是否一致、章节层级是否完整 —— 不一致就在画布上手动连 BELONGS_TO。

## 八、关于"AI 全做 vs 人工抽检"

HTML 文档的判断很对：**AI 做 90% 生产，人做 10% 规则制定 + 抽检**。系统当前的 candidate / approved 双状态机就是为这个设计的：

- AI 生成 → 全是 candidate（虚线展示）
- expert 在 ReviewPanel 逐条 approve / reject → 转 approved（实线）
- 只有 approved 的节点 / 关系才会进入后续的检索和 Agent 调用（这层接口预留了，待 RAG 期）

**所以你只要把"模板 + Schema + 评测题"三件事做扎实，就是 HTML 里说的核心壁垒。**
